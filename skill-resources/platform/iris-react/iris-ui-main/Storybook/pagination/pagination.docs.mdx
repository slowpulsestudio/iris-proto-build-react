# Pagination

`iris-pagination` is a controlled component. It renders navigation UI from `currentPage`, `totalPages`, `maxVisiblePages`, and `type`, then emits `pageChange` when the user asks for a different page. It does not update `currentPage` internally.

## When to use

| Type | Use when |
| -------------- | ----------------------------------------------------------------------------- |
| **Default** | Users need direct access to specific pages. |
| **Simplified** | Only previous/next navigation is needed. |

## Default

Default mode renders Previous, numbered page buttons, and Next. The first and last page are always present. When `totalPages` is greater than `maxVisiblePages + 2`, the middle range is collapsed with separator items.

## Navigation bounds

Previous is disabled on the first page. Next is disabled on the last page. Clicking the current page button does nothing.

## Few pages

When `totalPages <= maxVisiblePages + 2`, every page number is shown and no separators are inserted.

## Accessibility

- The root element is `<nav>` with an accessible label. The label defaults to `"Pagination"`; override `ariaLabel` when a page has multiple navigation landmarks or when a localised label is needed.
- The active page button gets `aria-current="page"`.
- In default mode, Previous and Next use labelled icons (`Previous page` and `Next page`).
- In simplified mode, the visible `Previous` and `Next` text provides the accessible name.
- The component does not implement custom keyboard shortcuts; it relies on native button behaviour.

## API

<ArgTypes of={PaginationStories} sort="alpha" />

### PaginationChangeEvent

Emitted by `pageChange` whenever the user navigates to a different page. All values are 1-based.

| Property | Type | Description |
|---|---|---|
| `page` | `number` | The requested next page. |
| `previousPage` | `number` | The page that was active before the interaction. |
| `totalPages` | `number` | Total pages at the time of emission. |
