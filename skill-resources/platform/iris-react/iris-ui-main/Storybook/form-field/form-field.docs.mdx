# FormField

`iris-form-field` is a composition wrapper for a projected `iris-label`, a projected control, and projected `iris-subtext` content. It has no inputs or outputs of its own. Instead, it reads the first projected `IrisFormControl` provider to derive invalid, touched, required, and count state, then forwards required and count information to `iris-label`.

## Basic usage

```html
<iris-form-field>
  <iris-label>Email address</iris-label>
  <iris-textinput placeholder="you@example.com" formControlName="email"></iris-textinput>
  <iris-subtext type="hint">We'll never share your email with anyone.</iris-subtext>
</iris-form-field>
```

## Label info tooltip

`iris-label` supports `infoText`, which shows an info icon and tooltip next to the label. This works the same way inside `iris-form-field` because the label is projected content. Use `infoTooltipPosition` when the tooltip should prefer a different direction in tighter layouts.

```html
<iris-form-field>
  <iris-label infoText="We use your work email for account notifications and security verification." infoTooltipPosition="right">
    Email address
  </iris-label>
  <iris-textinput placeholder="you@example.com"></iris-textinput>
  <iris-subtext type="hint">Hover or focus the info icon next to the label.</iris-subtext>
</iris-form-field>
```

## Validation errors

Error display is driven by the projected control's `isInvalid` and `isTouched` signals. When the control is both invalid and touched, the form field shows only the first projected `iris-subtext type="error"` and hides every hint. When the control is valid or untouched, it shows only the first projected `iris-subtext type="hint"` and hides every error.

Projected order matters: place the highest-priority hint or error first.

```html
<iris-form-field>
  <iris-label>Email</iris-label>
  <iris-textinput [formControl]="emailControl" placeholder="you@example.com"></iris-textinput>
  <iris-subtext type="hint">Enter your work email address.</iris-subtext>
  @if (emailControl.hasError('required')) {
    <iris-subtext type="error">Email is required.</iris-subtext>
  }
  @if (emailControl.hasError('email')) {
    <iris-subtext type="error">Enter a valid email address.</iris-subtext>
  }
</iris-form-field>
```

## Auto required indicator

When the projected control reports `isRequired() === true` through the `IrisFormControl` token, `iris-label` shows its required text automatically.

## Without subtext

`iris-subtext` is optional. If no matching hint or error is projected, nothing is rendered below the control.

## Large size

`iris-form-field` does not have a size input. Any larger control styling comes from the projected control itself.

## Accessibility

- `iris-form-field` does not add ARIA attributes, roles, or keyboard handlers.
- Required state, validation semantics, and accessible naming come from the projected control and supporting content.
- The wrapper only coordinates which projected hint or error text is visible.

## API

`iris-form-field` is configured through projected children rather than component inputs.

### Projected slots

| Slot | Typical content | Required | Notes |
|---|---|---|---|
| Label | `<iris-label>` | Recommended | Receives required and count state from the form field context. |
| Control | A component that provides `IrisFormControl` | Yes | The form field reads `isInvalid`, `isTouched`, `isRequired`, `countValue`, and `countMax` from this token. |
| Hint | `<iris-subtext type="hint">` | Optional | Only the first projected hint is shown, and only while no error is being shown. |
| Error | `<iris-subtext type="error">` | Optional | Only the first projected error is shown, and only while the control is invalid and touched. |
